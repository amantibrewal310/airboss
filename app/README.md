# Airboss app

The Mac app's user interface: Svelte 5 (runes only) on Vite, in a Tauri 2 shell. The Rust side
lives in `src-tauri/`. The contract between them is [SPEC-app.md](../SPEC-app.md), Appendix A
(commands) and B (events), with the types generated from Rust; the look is
[DESIGN.md](../DESIGN.md).

## Run it

Node 24 and pnpm.

```
pnpm install
pnpm exec playwright install webkit     # once, for component and end-to-end tests
pnpm dev:mock                           # the UI in a browser on the mock backend, http://localhost:5173
AIRBOSS_DB=$(mktemp -d)/a.db pnpm tauri dev   # the real app on a throwaway database
```

## Build the app

```
pnpm bundle --bundles app        # the same as: pnpm tauri build --config src-tauri/tauri.bundle.conf.json --bundles app
pnpm bundle --bundles app,dmg    # and the .dmg
```

Both land in `../target/release/bundle/`. `tauri.bundle.conf.json` adds the `airboss` CLI as
the bundle's sidecar (`bundle.externalBin`), and `beforeBuildCommand` builds it in release first
(`src-tauri/scripts/build-sidecar.sh`). It's kept out of `tauri.conf.json` on purpose:
tauri-build copies a configured sidecar next to whatever it builds, so with it there every
`cargo build` or `cargo test` of the app put an empty stand-in over `target/debug/airboss` and the
CLI's tests failed. Don't rename it `tauri.macos.conf.json`, which tauri-build merges by itself.
A plain `pnpm tauri build` makes an app with no CLI inside.

`pnpm tauri dev` needs Rust (the toolchain in `../rust-toolchain.toml`). Without `AIRBOSS_DB` it
uses your real database in `~/Library/Application Support/Airboss`. The webview's errors and
warnings print in the same terminal.

The mock picks its data with `?fixture=`: `full` (default, about 60 tasks), `design` (the
design's sample data), `perf` (2,000 tasks), `empty` and `welcome` (first run), `t3missing`,
`nothing` and `dberror`, or `recorded`: Rust's own answers from `src/lib/mock/fixtures/recorded.json`
(reads only; writes must follow its script). `?view=all&select=144` starts somewhere other than
Needs me. The quick-add panel is at `/quickadd.html`.

## Check it

```
pnpm check        # svelte-check and tsc, warnings fail
pnpm test         # Vitest: unit tests in Node, component tests in WebKit
pnpm test:e2e     # Playwright on the mock build: smoke, 60 fps, focus, layout at 1100 and 1440,
                  # axe in both themes and Increase Contrast, the recorded fixtures, 24 screenshots
pnpm build        # dist/ for Tauri (index.html and quickadd.html)
```

`pnpm test:e2e` starts its own preview on port 4173 and stops if the port is taken, so it never
tests another worktree's build. `pnpm exec playwright test --update-snapshots` rewrites the
baselines in `tests/e2e/baselines/`. Compare any change with `docs/design/screens/` before you
commit new ones.

After a change to `src-tauri/src/dto.rs` or to the scripted writes in `tests/script.json`, run
`cargo test -p airboss-app --test fixtures` from the repo root. It regenerates
`src/lib/types/generated/types.ts` and `src/lib/mock/fixtures/recorded.json`, and
`tests/component/recorded.test.ts` then checks that the UI sends exactly the recorded writes.

## Layout

| Path | What |
|---|---|
| `src/lib/types/` | The DTOs, generated by ts-rs from `src-tauri/src/dto.rs` into `generated/types.ts`. Don't edit them by hand. Everything imports them through `index.ts`. |
| `src/lib/api/` | `contract.ts` (every command and event with its types), `index.ts` (one function per command), `transport.ts`, `tauri.ts` |
| `src/lib/mock/` | The browser's backend: model, row builder, write handlers, undo, attention stand-in, and `replay.ts` for the recorded script. `fixtures/index.ts` is the one loader: the hand-made fixtures, and `loadRecording()` for Rust's `recorded.json`. |
| `src/lib/state/` | Stores (`*.svelte.ts`) and the controller (`app.svelte.ts`) that holds every action |
| `src/lib/logic/` | Pure, tested logic: views, selection, virtual-list maths, patches, keymap, focus zones, the command registry, search, run-map layout, links, time, connections, launch toasts |
| `src/lib/components/` | Small parts: StatusIcon, ProgressRing, StackedBar, LiveChip, Avatar, Kbd, Button, Menu, Popover, Modal, VirtualList… |
| `src/windows/main/` | The main window: sidebar, list, panel, page, run map, Needs me, Plans, overlays, first run |
| `src/windows/quickadd/` | The quick-add panel (its own entry page) |
| `tests/unit`, `tests/component`, `tests/e2e` | Vitest (Node), Vitest (WebKit), Playwright (WebKit) |
| `tests/script.json` | The writes Rust records into `recorded.json` (used instead of `src-tauri/tests/fixtures/script.json`) |

No component library, no CSS framework, no state or virtual-list library: plain CSS on the
tokens in `src/styles/tokens.css`.
